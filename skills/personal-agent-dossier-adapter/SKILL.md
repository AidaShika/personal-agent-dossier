# 为你的平台写 personal-agent-dossier 适配器

English version: [SKILL.en.md](SKILL.en.md)

你是某个平台里的 agent。你比任何外人都清楚本平台怎么存提示词、记忆和定时任务，所以适配器由你来写。规范和测试由仓库统一管，你只负责把本平台接上去。

## 你需要的东西（都在这个仓库里）

| 路径 | 用途 |
|---|---|
| `SPEC.md` | 格式规范，先完整读一遍 |
| `tests/fingerprint-vectors.json`、`tests/check_vectors.py` | 指纹的标准答案，任何实现都必须先通过 |
| `examples/scribe.dossier.md` | 虚构示例，有定时任务和三类记忆，拿它做往返测试 |
| `docs/conformance-test.md` | 导入方一致性测试任务 |
| `tools/render_notion.py` | 把档案生成 Notion 页面正文（选 Notion 存储时用） |
| `adapters/grok-bot/` | 参考实现（一个导出器，一个只读的空跑导入器），可以抄结构，不要抄路径 |

## 步骤

1. **读规范，定目标等级。** 读完 `SPEC.md`，看第 6.1 节，决定适配器要做到 L0、L1 还是 L2。拿不准就先声明低一级，测过再升。
2. **画映射表。** 先不写代码，逐字段回答：这个字段在我的平台里放哪儿？

   | 档案字段 | 本平台放在哪里 | 还原程度（原样 / 降级 / 存不下） |
   |---|---|---|
   | id、name、title、role | | |
   | anti_jobs | | |
   | routines | | |
   | memory（含 kind、learned） | | |
   | skills、refs、group | | |

   存不下的字段不能静默丢掉，要进「丢失或降级清单」。
3. **先做指纹。** 用你平台的语言实现 SPEC 2.1 节的算法，跑完 `tests/fingerprint-vectors.json` 的全部向量，全部通过才往下走。常见坑：
   - 每一段都要先把 `\r\n` 换成 `\n`，再去掉首尾 Unicode 空白（包含全角空格和不换行空格）。
   - YAML 的 `|` 和 `|-` 末尾换行不同，所以必须 strip，不要依赖原始字节。
   - 如果你的平台把名字和职能标签拼成一个显示名（例如 Grok Bot 的「Hatch · Bot设计助手」），才需要按 ` · ` 拆开：`name` 取之前的部分，`title` 取之后的部分；有独立字段或没有 title 的平台直接填，title 省略。
4. **写导出器（本平台 → 档案）。**
   - 只导出你自己能读到的内容。别的 agent 的记忆不导出。
   - `role` 原样保留，不改写、不缩短。
   - 没导出的 routines 或 memory 写 `null`，确实没有才写 `[]`。
   - 导出前对 role、fact、prompt 扫描敏感信息（邮箱、日本电话号码、16 位卡号、`sk-` 和 `ghp_` 之类令牌、密码后面的值）。命中就中止并报告位置，不要自动改写。
   - 正文或 role 里出现其他 agent 的 id，写进 `refs`。
   - 幂等：连续导出两次，除 `exported_at` 外必须字节一致。
5. **写导入器（档案 → 本平台）。**
   - 先做空跑：只检查并打印「将要做什么」和「丢失或降级清单」，不创建、不修改任何东西。
   - 同时能读文件形式（front matter）和 Notion 形式（页面里唯一一个 ` ```yaml ` 块），以 YAML 为准。注意 Notion 取回文本时可能把 `[rule]` 转义成 `\[rule\]`。
   - 检查：必填字段、`spec` 版本（接受 0.1 和 0.2）、指纹重算对得上、敏感信息再扫一遍、memory 的 kind 合法。
   - 真正写入前必须得到用户确认。记忆默认只写到测试文件，不写进真实记忆。
   - `null` 要在报告里写成「未导出，不等于没有」。
6. **往返测试。** 用 `examples/scribe.dossier.md`：导入 → 再导出 → 比较，说明哪些字段还原了、哪些变了。再按 `docs/conformance-test.md` 把测试做一遍。
7. **交付。** 放进 `adapters/<平台名>/`，带一个简短 README，写明：声明的等级、映射表、已知降级、怎么运行。再写一份适配器报告（模板见下）。

## 适配器报告模板（`adapter-report.md`）

1. 平台名称、声明的等级（L0 / L1 / L2）
2. 指纹向量结果：`PASS n vectors` 或失败的向量
3. 映射表（第 2 步那张，填完整）
4. 往返测试结果：还原了什么、变了什么
5. 丢失或降级清单
6. 规范反馈：规范里哪里含糊、哪里和你的平台冲突（只写在这里，不要改 `SPEC.md`）
7. 没测的部分，以及为什么

## 不要做的事

- 不修改 `SPEC.md`、测试向量和示例。规范有问题就写进报告第 6 项。
- 不导出别的 agent 的记忆，不导出个人信息。仓库、档案和报告里都不放地址、电话、证件、账号密码、令牌。
- 不凭猜测写平台行为。拿不准的地方，先在你的平台上试一遍再写。
- 不静默丢字段，不把 `null` 当成空。
- 不发送邮件或消息，不联系第三方。
- 不在没得到用户确认时写入真实的 agent、记忆或定时任务。
